# opencode-claude-code

An experimental **OpenCode 2 TypeScript/Effect plugin**, adapted from
[pi-claude-code](https://github.com/earendil-works/pi-claude-code).
No Meridian or Claude Agent SDK dependency.

OpenCode owns tools, approvals, history, and compaction. The official `claude`
CLI owns authentication and talks to the model. Its MCP tools are inert: only
OpenCode executes the returned tool calls.

## Local installation

Requires OpenCode **2.0.26**, Node **22.19+**, pnpm **11**, and an installed,
authenticated Claude Code CLI:

```sh
claude auth login
pnpm install --frozen-lockfile
pnpm build
```

Append the absolute **dist directory** to your OpenCode configuration's plugin
list, preserving existing entries:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": ["/home/ben/dev/opencode-claude-code/dist"]
}
```

Restart the background service if necessary (`opencode2 service restart`), then
select **Claude Code Subscription (Experimental)**. Models are discovered from
your installed Claude CLI. For example:

```sh
opencode2 run --model claude-code/sonnet "Hello"
```

No Anthropic provider override or placeholder credentials are needed in your
configuration. Other providers are untouched. If Claude is absent or logged
out, this plugin does not register its provider; sign in and reload it.

## Nix

```sh
# path: also includes new files in an uncommitted development checkout.
nix build path:.
```

The plugin is at `result/lib/opencode-claude-code`. The package contains compiled
JavaScript and the inert MCP asset, but no node_modules. OpenCode supplies Effect
and its plugin API. Nix pins Node for the MCP subprocess; `claude` remains a
separately installed program.

To integrate into `~/dev/nix-configs/nixcfg`, add a flake input (a local checkout
while developing; a Git URL once published):

```nix
inputs.opencode-claude-code.url = "path:/home/ben/dev/opencode-claude-code";
```

Then append this to the plugin list generated by your existing Hjem module in
`modules/system/programs/ai/opencode/mod.nix`:

```nix
"${inputs.opencode-claude-code.packages.${system}.default}/lib/opencode-claude-code"
```

That Hjem config currently uses the compatible legacy `plugin` list. Append
there; do not introduce a second `plugins` list that overrides its other entries.

Use this flake's pinned nixpkgs for the package initially; no overlay, wrapper,
Home Manager module, or runtime package installation is required. Adding a
plugin path also keeps its store output alive through the generated config.

## Options

```jsonc
{
  "plugins": [{
    "package": "/path/to/plugin/dist",
    "options": {
      "claudeCommand": "/absolute/path/to/claude",
      "configDir": "/home/me/.claude"
    }
  }]
}
```

Optional environment equivalents:

- `OPENCODE_CLAUDE_CODE_COMMAND`: Claude executable; defaults to `claude` on PATH.
- `OPENCODE_CLAUDE_CODE_CONFIG_DIR`: passed to Claude as `CLAUDE_CONFIG_DIR`.
- `OPENCODE_CLAUDE_CODE_NODE_COMMAND`: MCP Node executable; defaults to `node`
  locally, or a pinned absolute store path in the Nix build.
- `OPENCODE_CLAUDE_CODE_ALLOW_USAGE_CREDITS=1`: opt into usage credits.

`nodeCommand` is also available as a plugin option. Explicit executable paths
avoid differences between the background service's PATH and your shell's PATH.

## Billing and limitations

Like Pi, the bridge rejects ambient API-key, proxy, Bedrock, Vertex, and Foundry
overrides, and stops when Claude reports usage-credit overage. **That first
request has already been charged**; disable usage credits in Claude settings if
you need a stronger billing boundary. Subscription access, pricing, and policies
can change independently of this plugin; this is not an eligibility guarantee.

The CLI/relay behavior is adapted from Pi, not reimplemented through another SDK.
The OpenCode-specific code uses its native Anthropic transport and a random,
loopback-only endpoint. The relay captures upstream thinking signatures, tool
arguments, usage, and stop reasons before Claude processes them, and permits one
upstream request per turn. Stable native reminder metadata is saved in plugin
storage; credentials are never saved there.

Initial differences from Pi:

- Every request uses a fresh CLI process; no warm-process reuse yet.
- Tool schema simplification follows Pi's limitations.
- Tool-set changes replay with the current inventory; Pi's optimized deferred
  tool/cache layout is not implemented.
- An unspecified thinking preference uses Claude Code's default rather than
  forcing `disabled`, which newer models reject.
- Tool-call events are released after CLI billing checks; text/thinking stream
  immediately. OpenCode owns local summary compaction.

## Checks

```sh
pnpm check
pnpm test
pnpm build
pnpm smoke                 # opt-in: real Claude login and subscription quota
pnpm smoke /path/to/nix/store/output/lib/opencode-claude-code
```

The focused fixtures cover schema/history translation, signed thinking, relay
capture, tool round trips, cancellation, and billing guards. A fixture-backed
OpenCode 2 tool round has passed using the Nix-store package. A real-account
Sonnet smoke test has also passed: Claude requested a file read, OpenCode executed
it, and Claude continued with the expected file contents.
Smoke tests use isolated OpenCode config/data and leave their temporary directory
for inspection; they do not change your global config or restart your service.
